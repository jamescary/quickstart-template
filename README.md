# quickstart-template

A Cloudflare-native full-stack starter that comes with an **agent-driven setup skill**. Clone the repo, ask Claude Code to run `quickstart-setup`, and the skill interviews you, provisions Cloudflare resources, customizes the codebase to your toggle choices, scaffolds a starter feature, then self-removes — leaving a working, deployable project tailored to your needs.

## Quick start

```bash
curl -fsSL https://raw.githubusercontent.com/jamescary/quickstart-template/main/install.sh | bash -s -- my-app
cd my-app
# Open a Claude Code session here and ask: "run quickstart-setup"
```

If you don't want to pipe `curl` into `bash`, see [INSTALL.md](./INSTALL.md) for a manual clone walkthrough.

## What's in the box

- **Framework:** TanStack Start (React, file-based routing, server functions)
- **Hosting:** Cloudflare Workers via `@cloudflare/vite-plugin`
- **Database:** Cloudflare D1 + Drizzle ORM
- **KV:** Cloudflare Workers KV
- **Auth:** better-auth + `better-auth-cloudflare` (GitHub + Google OAuth, optional org plugin)
- **Realtime:** Cloudflare Durable Objects (optional presence-widget example)
- **Email:** Resend (optional, with dev-mode console fallback)
- **UI:** Tailwind v4 + shadcn/ui (`new-york`)
- **Tests:** Vitest + `@cloudflare/vitest-pool-workers` (optional)
- **Package manager:** pnpm

Each feature is **opt-out** during setup. The skill subtracts opted-out features (deletes files, strips marker regions, trims `package.json` deps), substitutes project sentinels, regenerates the auth schema for your chosen plugins, scaffolds your starter feature, and verifies the build before self-removing.

## How the setup skill works

The skill (`.claude/skills/quickstart-setup/`) is auto-loaded by Claude Code after the bootstrap. It runs in seven phases:

1. **Identity** — name, slug, description, brand color
2. **Toggles** — OAuth providers, org plugin, Resend, Durable Objects, Vitest, GitHub Workers Git Integration
3. **First feature** — 1–2 sentence description of what to scaffold
4. **Cloudflare provisioning** — creates a D1 database and KV namespace, writes IDs into `wrangler.jsonc`
5. **Credentials** — walks you through each chosen OAuth provider's console, collects keys, writes `.dev.vars`
6. **Confirmation** — summary block; requires explicit `yes` before any source file is mutated
7. **Apply** — subtraction, sentinel substitution, brand color, schema regen, migration regen, feature scaffold, types regen, build verification, optional GitHub repo + Workers Git Integration, then self-removes

See the [design spec](./docs/superpowers/specs/2026-04-30-quickstart-template-design.md) for the full architecture, including the **subtractive transformation** strategy that lets the template ship every feature wired up while still subtracting cleanly per user choice.
